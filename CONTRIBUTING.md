# Contributing

Thank you for your interest in contributing to this companion repository.

## What to contribute

- Bug fixes in the implementation examples
- Additional usage examples for existing contracts
- Corrections to code that diverges from the book's intent

## What not to contribute

- New patterns not covered in the book
- Alternative implementations of the same contract
- Dependencies beyond the standard stack

## Process

1. Fork the repository
2. Create a branch: `git checkout -b fix/chapter-name-description`
3. Make your change
4. Open a pull request with a brief description

All contributions must match the style and intent of the existing code.
